# CFA-Agent 多智能体技术方案

> 基于 LangChain + LangGraph + SQLite 的 Supervisor 多智能体系统
> 支持 Tools、Skills、MCP，具备内省与自主闭环能力

---

## 一、总体架构

```
API Gateway (FastAPI) → Supervisor 调度层 (LangGraph) → 专家智能体层 → 能力层 (Tools/Skills/MCP/Memory) → 持久化层 (SQLite)
```

| 层级 | 技术栈 | 职责 |
|------|--------|------|
| API 网关层 | FastAPI + SSE + WebSocket | RESTful 接口、流式响应、文件上传 |
| Supervisor 调度层 | LangGraph ReAct + delegate | 单一入口，委派任务，验证结果 |
| 专家智能体层 | LangGraph ReAct | 独立 ReAct 循环，被 Supervisor 按需调用 |
| 能力层 | Tools + Skills + MCP + Memory | 共享服务：工具注册、技能模板、MCP 双向集成、记忆检索 |
| 持久化层 | SQLite + FTS5 + sqlite-vec | 状态持久化、全文检索、向量检索、审计日志 |

## 二、Supervisor 多智能体设计

### 2.1 角色定义

| 角色 | 职责 | ReAct 侧重 |
|------|------|------------|
| **Supervisor**（监督者） | 唯一入口、任务调度、结果验证 | think 侧重分类与委派；verify 验证结果质量 |
| **Planner**（规划者） | 任务分解、策略制定 | think 侧重分解与子任务生成 |
| **Executor**（执行者） | 工具调用、任务执行 | think 侧重工具选择与参数构造 |
| **Reviewer**（审查者） | 结果校验、质量把关 | think 侧重校验与偏差检测 |

> **Agent 由配置驱动**：角色定义在 `config/agents.yaml`，支持在不修改代码的情况下新增/修改 Agent。

### 2.2 协作流程

Supervisor 是唯一入口，用户请求到达后：

1. **think**：判断任务类型（简单直接回答 vs 复杂委派）
2. **act**：通过 `delegate` 工具委派给专家（Planner → Executor → Reviewer）
3. **observe**：收集专家返回结果
4. **verify**：验证结果质量，不通过则重新委派（最多 2 次）
5. **answer**：汇总输出给用户

### 2.3 Supervisor 决策规则

| 输入类型 | 决策 |
|---------|------|
| 问候/闲聊 | 直接回答 |
| 数学/编程/检索 | 委派给 Executor |
| 复杂多步骤 | 先委派 Planner，再委派 Executor |
| 需要验证 | 委派 Reviewer |
| 结果不满足 | 重新委派（最多 2 次） |

### 2.4 委派机制

`delegate` 工具是 Supervisor 专用的调度工具：
- 从 AgentService 获取目标 Agent 配置
- 创建目标 Agent 的独立 ReActGraph
- 启动独立 ReAct 循环，同步等待完成
- 返回结果给 Supervisor

特点：同步阻塞、独立上下文、透明传递、角色隔离。

### 2.5 verify 自修正闭环

Supervisor 输出前必须经过 verify 验证：
- 通过 → 输出给用户
- 不通过 → 返回 think 重新委派（附带修正建议）
- 非 Supervisor 的 Agent 不启用 verify（由配置 `enable_verify` 控制）

## 三、会话管理与多轮对话

- **会话生命周期**：创建 → 活跃 → 暂停 → 归档
- **上下文注入**：会话历史、用户偏好、文件上下文注入到 think 节点
- **存储**：SQLite 持久化，支持会话恢复和历史查询

---

## 四、Tools 与 Skills 系统

### 4.1 Tools 系统

- **定义规范**：遵循 OpenAI Function Calling 规范
- **内置工具**：web_search、text_processing、file_ops、code_executor、api_caller、data_analysis、delegate
- **工具注册**：ToolRegistry 统一管理，支持动态注册/注销
- **工具过滤**：每个 Agent 只暴露 `agents.yaml` 中配置的工具，实现权限控制

### 4.2 Skills 系统

- **定义规范**：Markdown 文件，包含触发词和提示词模板
- **工作原理**：think 节点根据任务描述匹配触发词，注入对应技能提示词
- **内置技能**：数据分析、代码审查、文本处理、搜索增强
- **与 Tool 协作**：Skill 提供"怎么做"的知识，Tool 提供"做什么"的能力

---

## 五、MCP 双向集成

- **MCP Client**：作为消费者连接外部 MCP Server，动态注册外部工具
- **MCP Server**：作为提供者暴露 CFA-Agent 能力给外部客户端
- **传输协议**：支持 stdio、SSE、Streamable HTTP
- **配置管理**：`config/mcp_servers.yaml` 管理外部 MCP 连接

## 六、内省系统

### 6.1 状态机

内省状态与 ReAct 节点一一对应：THINKING → ACTING → OBSERVING → REFLECTING → VERIFYING → ANSWERING

### 6.2 核心能力

- **偏差检测**：检测任务偏离、死循环、工具滥用
- **置信度评估**：评估当前推理方向的可信度
- **健康检查**：监控 Token 消耗、步数、响应时间

## 七、ReAct 自主闭环

### 7.1 六节点工作流

think → act → observe → reflect → verify → answer

| 节点 | 职责 |
|------|------|
| think | LLM 推理决策，决定工具调用或直接回答 |
| act | 执行工具调用，返回结果 |
| observe | 观察执行结果，Token 溢出检测 |
| reflect | 反思当前策略，方向修正 |
| verify | 结果验证（Supervisor 自修正核心） |
| answer | 生成最终回答 |

### 7.2 条件路由

从 think 出发：
- 有 tool_calls → act
- 需要反思 → reflect
- 直接回答 → verify（先验证再输出）
- 超出步数/上下文溢出 → answer

从 verify 出发：
- 通过 → answer
- 不通过 → think（重新委派）

### 7.3 关键特性

- **死循环检测**：相同 tool_calls 连续出现 3 次触发 reflect
- **上下文溢出处理**：Token 溢出时自动压缩历史或直接输出
- **Checkpoint 持久化**：每个步骤保存状态，支持中断恢复
- **记忆检索**：think 节点从 MemoryManager 检索相关历史经验
- **流式推送**：SSE 实时推送 think/act/observe 事件
- **错误恢复**：LLM 调用失败、工具执行超时、网络异常均有降级策略

## 八、SQLite 数据库设计

### 8.1 选型理由

零外部依赖、开箱即用、支持 FTS5 全文检索和 sqlite-vec 向量检索。

### 8.2 核心表

| 表名 | 用途 |
|------|------|
| agents | Agent 配置与状态 |
| agent_tool_bindings | Agent 与工具的绑定关系 |
| tasks | 任务记录与结果 |
| sessions | 会话管理 |
| episodic_memory | 情景记忆 |
| semantic_memory | 语义记忆（含向量嵌入） |
| procedural_memory | 过程记忆（成功模式） |
| events | 事件与审计日志 |
| mcp_servers | MCP 服务器配置 |

## 十一、设计优势

| 特性 | 说明 |
|------|------|
| **配置驱动** | Agent 由 YAML 定义，新增/修改无需改代码 |
| **单一入口** | Supervisor 统一调度，用户无需关心内部结构 |
| **自修正闭环** | verify 节点验证结果，不通过自动重试 |
| **工具权限控制** | 每个 Agent 只暴露配置的工具，降低幻觉 |
| **零外部依赖** | SQLite 持久化，开箱即用 |
| **双向 MCP** | 既消费外部工具，也暴露自身能力 |
| **全链路护栏** | 输入/输出/行为/工具/安全五层检查 |
| **三级记忆** | 情景/语义/过程记忆，支持向量检索 |

---

## 十二、总结

CFA-Agent 采用 **Supervisor 多智能体架构**，以配置驱动的方式定义 Agent 行为，通过 ReAct 自主闭环实现任务推理与执行。核心设计思想：

- **委派而非调用**：Supervisor 通过 `delegate` 工具委派任务，专家独立完成
- **验证闭环**：输出前必须验证，不通过则修正重试
- **配置即代码**：Agent 行为由 YAML 定义，Prompt 和工具均可配置
- **能力分层**：Tools 提供执行能力，Skills 提供领域知识，MCP 提供外部集成
